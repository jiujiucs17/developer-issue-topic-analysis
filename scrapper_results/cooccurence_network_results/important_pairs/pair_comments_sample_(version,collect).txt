My understanding is that this happens because Distribution's  default property design of standard deviation is defined with respect to the variance, and, even if you have a negative standard deviation, the square root of the square of it will still be positive.
Obviously this is a bug that would only occur in cases where surrounding code has done something incorrect and initialized a Normal with invalid negative standard deviation values, but since the initialization of the Normal doesn't automatically set the validate_args flag to True, and thus doesn't prevent the creation of invalid Normals, this wrapper-level bug can make it more difficult to debug problems. In my case, wrapped_dist.log_prob(vec) was returning nans, and when I checked my first-guess potential issues (that activations to keep stddev positive had not been applied properly), I was told the wrapped_dist.stddev was in fact positive, even though, upon further examination of the base_dist, I learned base_dist.stddev was partially negative, and, since that is what is used to calculate the log probability, that was indeed the cause of my errors
