🐛 Describe the bug
I observed a deadlock while training on GPU. Narrowed it down to two threads:
Thread 553 C++ stack

Thread 553 Python stack

Thread 1 C++ stack

Thread 1 Python stack

I believe what is happening here is:

Thread 1 is attempting to allocate memory through the DeviceCachingAllocator, which (when memory history recording is enabled) eventually calls back into the GIL to release the recorded back-trace for an allocation. Thread 1 blocks on the GIL, which thread 553 holds.
Thread 553 is also attempting to call into the DeviceCachingAllocator while holding the GIL (since THPStorage_resize_ calls into the allocator but does NOT free the GIL). Since thread 1 holds the DeviceCachingAllocator, Thread 553 blocks waiting for Thread 1 to release it

It may be that we need to enforce that all callers of the CachingAllocator must release the GIL
