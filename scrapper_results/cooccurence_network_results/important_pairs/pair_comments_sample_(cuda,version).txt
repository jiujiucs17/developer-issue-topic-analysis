🐛 Bug
Assume you want to load a model using torch.hub. For instance:
torch.hub.list('githubaddress', 'model', pretrained=True)
Now assume in your own project you have a package named 'models',
Also assume that the external github repository has also a package named 'models'.
torch.hub.load invokes ->   torch.hub.import_module invokes -> importlib.util.exec_module
Unfortunately, the importlib confuses the local models package with the external models package!
To Reproduce
Steps to reproduce the behavior:

Make a project with a the following structure:

a.py




models

init.py








Add following to a.py
import torch  from models import *  print(torch.hub.list('facebookresearch/deit:main'))
The list will be empty, where if you really look into the github repository or comment out the line from models import * you see there are many models available.

Expected behavior
I expected that the users of torch.hub, either users who publish models or users who use the published models could develop their own projects without any concerns about what package names has the other side been using. This makes it impossible to think of published models as black-box easy-to-use plug-in-and-play models.
