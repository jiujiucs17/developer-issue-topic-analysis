🐛 Bug
Saving multiple model instances during training, if the save name used is the same, causes no leak. However when model is being saved with different names (e.g. via an index), the free memory goes down and moves (leaks) into buffer/cache memory . Also the buffer/cache memory does not get release by os after the code exits on its own.
To Reproduce
Steps to reproduce the behavior:

Open a terminal and type "watch -n 5 free -m" to monitor the memory usage
Run the simple example in a separate terminal (given below). You can use less iterations for the simple example.
Observe the decrease in free memory and the increase in the buffer/cache memory which does not get released even after the code exits.
However, the program does not crash. The free memory stabilizes and fluctuates around 400-800 megabytes. The used memory stabilizes around 3500 megabytes and buff/cache memory also stabilizes around 58GB.
You need to forcefully release the memory via typing in a terminal: " sudo sh -c 'echo 3 >/proc/sys/vm/drop_caches' ".
