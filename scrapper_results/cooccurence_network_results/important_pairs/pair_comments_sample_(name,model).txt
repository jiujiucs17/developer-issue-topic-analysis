🚀 The feature, motivation and pitch
It seems that FX isn't playing nice with any instance methods except forward: pytorch/vision#5197 (comment). It prevented factoring out initialization into a separate method, and it also seems to trigger consideration of review / retiring existing reset_parameters methods for torchvision models as they don't play nice with FX.
This also seems to prevent reset_parameters being supported, as additional instance methods will not work after FX (?)
Methods of this kind exist in practically all models, but have different names: reset_parameters, _reset_parameters, _init_parameters etc
Related issues: pytorch/vision#3410, #66335
Periodically reinitializing parts of model is useful in some training scenarios, as it can prevent overfitting (e.g. used in http://cvlab.postech.ac.kr/~jeany/ACCV2018_forget_and_diversify.pdf) and being able to do it inplace is nice as it saves memory and potentially heavy constructor calls. It's also nice for having this init code in separate methods for preventing time-consuming code navigation and copy-pasting of it (in majority of scenarios when FX isn't used)
Another times, this is useful to do as workaround for bugs like this: #72253
